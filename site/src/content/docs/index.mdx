This is the **specification**, not a package. Nothing here compiles or ships; what it
produces is a contract that other repositories transform into real UI kits — one for
Flutter today, others to follow.

Every value on this site is resolved from the spec's own token files and contracts when
the site is built. Nothing is retyped, so a page cannot disagree with the spec.

## What a specification is for

**Convergence.** Two teams implementing this independently, on different platforms, should
arrive at the same behaviour. That is a stronger property than being *buildable* — a vague
contract is buildable, just differently by each reader.

Anything a reader has to decide for themselves is a place where implementations diverge.

## Theme-first

Appearance lives on the platform's **global theming mechanism**, never in a wrapper
widget. Native widgets inherit the Flowin look; a component resolves only the per-call
concerns a theme cannot know — which variant, which size.

Custom components exist only where a platform has no equivalent.

<Aside title="The accent roles are neutral on purpose">
`primary`, `secondary` and `tertiary` alias the neutral ramp — see
[Colour](./tokens/colour/). That is the default, not a missing palette: colour in this
system is reserved for meaning, so only the status roles are chromatic.

They are the slots an application re-points to introduce its own accent, which is why a
transform must keep them overridable at the theme level rather than resolving them to
fixed values.
</Aside>
